#### `services/langGraphService.ts` ⭐⭐⭐⭐⭐
**职责**：LangGraph 工作流编排（**核心中的核心**）

**工作流节点**：
```typescript
// 1. 初始化（上下文管理）
initializeNode(state: WorkflowState, onStateUpdate?: StateUpdateCallback)
  → 滑动窗口压缩（50 条 → 摘要 + 最近 10 条）
  → 提取用户输入
  → 构建 contextInfo

// 2. 意图分类
classifierNode(state, onStateUpdate)
  → 调用 LLM 分类意图（task/chat/question）
  → 非任务直接返回聊天回复

// 3. 项目规划 ⭐
plannerNode(state, onStateUpdate)
  → 分析需求 + RAG 结果 + 已生成文件
  → 制定文件列表（path、description、dependencies、priority）
  → 拓扑排序（App.js 最后）
  → JSON 解析失败时自动重试（max_tokens: 4000 → 6000）

// 4. 代码生成 ⭐
executorNode(state, onStateUpdate)
  → 检查是否修改现有文件
  → 注入所有已生成文件的上下文
  → 调用 LLM 生成/修改代码
  → 返回完整的 React 组件代码

// 5. 文件整合
integratorNode(state, onStateUpdate)
  → 规范化路径（移除 ./ 前缀）
  → 提取 exports
  → 存储到 generatedFiles

// 6. 静态路径分析 ⭐
pathCorrectionNode(state, onStateUpdate)
  → 扫描所有 import 语句
  → 检查目标文件是否存在
  → 收集错误路径
  → 调用 LLM 批量修复

// 7. Sandpack 路径审查 ⭐⭐⭐（创新）
sandpackPathReviewNode(state, sandpackErrors, onStateUpdate)
  → 解析 Sandpack 的真实编译错误
  → 匹配 5 种错误模式（Cannot find module 等）
  → 提取涉及错误的文件内容
  → 调用 LLM 精确修复
  → 只修改 import 路径，保持业务逻辑

// 8. 完整性审查 ⭐
reviewNode(state, onStateUpdate)
  → 检查项目结构是否完整
  → 判断是否遗漏关键文件（Header、Footer 等）
  → 如果未完成，返回补充任务列表
  → 触发循环补充（最多 3 轮）

// 主工作流
runDomAgentWorkflow(initialState, onStateUpdate, sandpackErrors)
  → 执行所有节点
  → 循环生成直到所有文件完成
  → 累积思考过程
  → 返回最终状态
```

**辅助函数**：
```typescript
// JSON 解析器（容错）
parseJsonFromResponse(content: string)
  → 移除 Markdown 代码块
  → 智能错误诊断
  → 截断问题提示

// 路径工具
getDirname(path: string)           // 获取目录名
resolveImportPath(file, import)    // 解析相对路径
```

**代码量**：~1100 行（项目最大文件）

**关键特性**：

## 代码组织原则

### 1. 单一职责原则（SRP）
每个文件只负责一个功能：
- ✅ `deepseekService.ts`：只负责 API 调用
- ✅ `ragService.ts`：只负责知识检索
- ✅ `langGraphService.ts`：只负责工作流编排

### 2. 分层架构
```
UI 层（pages/、components/）
   ↓
状态层（stores/）
   ↓
服务层（services/）
   ↓
数据层（data/）
```

**优势**：
- 依赖方向清晰（上层依赖下层）
- 易于测试（每层独立测试）
- 易于替换（如替换 AI 模型）

### 3. 依赖倒置原则（DIP）
高层不依赖低层细节，通过接口/类型隔离：
```typescript
// DomAgent.tsx 不关心 deepseekService 的实现
import { runDomAgentWorkflow } from '../services/langGraphService';

// langGraphService.ts 使用抽象的 chatCompletion
import { chatCompletion } from './deepseekService';
```

### 4. 开闭原则（OCP）
对扩展开放，对修改封闭：
```typescript
// 添加新节点，无需修改现有节点
const newNode = async (state, onStateUpdate) => {
  // 新节点逻辑
};

// 在主工作流中插入
state = await newNode(state, handleStateUpdate);
```
